# 卡牌基本算子 V1

版本：2026-10-28。目标是描述当前本地目录的全部卡牌效果，而不是只覆盖最初整理的常见效果。本文件是语义规范，**不是已实现的规则引擎，也不是 100% 规则正确性的认证**。

保留最初的核心表达，但补上组合结构：

> 卡牌 = 基础属性 + 能力集合。  
> 能力 = 生效方式 + 时机／条件 + 费用 + 选择 + 算子组合 + 参数／规则修饰。

`算子(对象, 参数)` 足以作为动作接口。单独的 `条件 → 算子` 不足以区分替代、持续、延迟、支付以及链上的不同处理步骤，必须加上这些结构。本文的登记表包含不同层次的词汇，不把它们都算成“最小原子”。

V1登记 **49个动作入口＋27个控制／修饰词汇**，另定义34个目录关键词／动作词／状态词的展开。49个入口包含支付、洞察等可展开的具名组合，目的是保留规则身份，不追求数学上的最小原子数。

## 2. 基础属性、对象和区域

### 2.1 定义、实例、上下文分开

| 层 | 内容 |
| --- | --- |
| 卡牌定义 | `cardId`、中英文名、类型集合、超类型、领域、标签、印刷 Energy／Power、基础战力、武装战力、能力、衍生物模板、构筑上限、额外传奇数 |
| 印刷来源 | `printingId`、语言、短编号、正／背面路径、系列、图片、原文、勘误及引用 |
| 游戏实例 | 实例 ID、拥有者、控制者、区域／地点、朝向、增益、强化、眩晕、已受伤害、贴附关系、持续效果 |
| 执行上下文 | 回合／阶段／优先权、链、战斗角色、事件历史、目标绑定、支付记录、最后已知信息、关联对象 |

类型用集合表示，单位／法术／装备不穷尽全体类型。衍生物是产生方式或身份，不等于增益计数物。装备两个文本区必须分开：`printedRulesText` 是装备自身规则，`printedEffectText` 在贴附时追加给宿主，其中的“我”指宿主。

`null`、零值和类别不适用是三种不同情况；不得把缺费用、缺战力当作零。

### 2.2 对象与引用

对象可为玩家、卡牌、场上实体、链上法术／能力、符文、增益计数物、战场或一次事件。集合选择保存拥有者／控制者、友敌、类型、标签、领域、战力、费用、朝向等筛选。

主要区域包括手牌、主牌堆、符文牌堆、废牌堆、放逐区、链、基地、战场、传奇区、选定英雄区。场上还区分地点。盖放、展示、强化、增益和进攻／防守角色不是独立区域。

“此处”“它原来的位置”“这样放逐的牌”“其中剩余的牌”均为绑定引用，必须保存来源和实例，不能重新搜索同名牌。拥有者与控制者分别保留。

## 3. 能力结构

### 3.1 生效方式

| 种类 | 表达 | 处理要求 |
| --- | --- | --- |
| 直接结算 | `结算 → 步骤` | 法术本身的指令，不凭空增加打出触发 |
| 事件触发 | `事件 + 触发条件 → 步骤` | 事件发生后产生待处理能力；触发条件和结算条件分开 |
| 主动能力 | `时机 + 费用 : 步骤` | 玩家主动发动，满足权限并处理费用 |
| 持续能力 | `只要条件 : 修饰` | 条件成立时持续适用，失效时停止；不重复触发 |
| 替代效果 | `若将发生事件 : 改为新事件／步骤` | 原事件被改写或取消，不是假装先发生再撤回 |
| 构筑／设置 | `构筑或设置时 : 选择／修改` | 如预选额外传奇，不是对局中的打出触发 |

`while I am buffed` 与 `when you buff me` 不同；前者是状态条件，后者要求一次实际成功的增益。`if` 在原句中的位置可能决定它属于触发条件还是结算指令（383.2）。

### 3.2 统一节点

以下是文档记法，不是现有代码接口：

~~~text
能力 {
  生效方式; 来源实例; 生效区域;
  时机权限; 事件筛选; 触发条件; 使用次数限制;
  费用及支付时点;
  选择 { 决策玩家; 候选集合; 数量范围; 是否目标; 绑定时点; 信息权限; };
  步骤 [ 算子(对象引用, 参数...) ];
  持续期限; 关联记录; 事件归属; 原始文本与规则依据;
}
~~~

每次操作返回实际结果：是否发生、实际数量、涉及实例、产生事件及结果引用。后续“若如此做”“因此被摧毁”“这样召出的符文”引用实际结果，不只检查玩家选择了什么。

### 3.3 组合语法

| 结构 | 含义 |
| --- | --- |
| 顺序 | A 后 B；B 是否要求 A 成功由原句决定，不能把所有 then 都当作 if-do |
| 同时／批次 | 一次处理一组；与逐个处理会产生不同的事件与清理 |
| 条件 | if／unless／否则；判断时点明确 |
| 可选 | 可选整个能力、支付或局部步骤，三者分开 |
| 模式 | 选择一个／多个模式、能否重复选、何时选择 |
| 重复 | 次数、每次重选政策、步骤间清理、是否创建独立链项 |
| 自反触发 `REFLEXIVE` | `Do this N times:` 按387–389创建 N 个待处理链项，不只是同一结算内循环 |
| 延迟 | 登记未来触发、替代或持续效果；不是当场提前执行 |
| 关联 | 跨步骤、能力和区域保存具体实例关系，不在同名来源间串用 |

## 4. 费用与资源

### 4.1 两层支付

Energy 与 Power 是不同资源；Power 带领域需求、可用领域组及通用支付规则。横置／回收符文可能产生资源，**产生资源与支付资源是两件事**。本目录也有横置产生领域 Power 的符文，不能预设所有符文都使用相同产费方式。

| 成本内容 | 参数 |
| --- | --- |
| 资源 | Energy、Power 数量、允许领域、资源来源及使用限制 |
| 横置对象 | 自身／单位／装备／传奇／符文，数量和合法状态 |
| 回收 | 自身、手牌、废牌或符文；所属牌堆和实际对象 |
| 弃置 | 数量、合法手牌、决定者 |
| 摧毁 | 自身／指定己方单位或装备，死亡与替代处理 |
| 消耗计数或状态 | XP、增益、解除强化，所属对象与数量 |
| 其他具名动作 | 放逐废牌、友军回手等，只有原句明确为费用时才作为费用 |

### 4.2 角色和时点

- 区分基础费用、额外费用、替代基础费用、指令内费用和动作附加费用（201–206）。
- 冒号前通常是主动能力基础费用；触发指令开头的“做 X 以做 Y”可能提升为其基础费用，须在定稿时支付（383.3）。
- `discard 1 and channel ...` 不等于 `discard 1 to channel ...`；不能把“并且”擅自改成费用连接。
- 费用须完整合法支付；一般效果按规则尽可能执行。费用动作被替代后依203.2仍可能算支付，不能仅凭原事件未发生就判未付。
- `pay ...; if you do ...` 与规则定义的费用连接也要区分；205明确某些是支付动作后检查实际结果。
- 忽略基础费用、忽略 Energy、忽略全部费用分别表达；不自动解除目标、时机或目的地限制。
- 降费不是返还资源；印刷费用、修改后费用、实际支付量分开。读取牌的费用遵守206，不擅用实际支付量代替。
- 已横置对象不能再次支付横置成本；零费用不制造一次正数资源支付事件。
- 产费能力适用430的即时定稿／结算规定，不为其虚构普通响应窗口。

## 5. 动作算子登记表

保留游戏中有独立身份的动作。终点相同不代表动作相同；“回手”一般是区域转移，抽牌、弃置、放逐、回收、摧毁保留各自事件。此表含少量具有独立规则身份的组合，允许展开，但不能消掉动作身份。

### 5.1 区域和地点

| ID | 签名 | 语义边界 |
| --- | --- | --- |
| `TRANSFER` | 区域转移(对象, 来源, 目的地, 次序) | 普通区域变化，不冒充其他具名动作 |
| `MOVE` | 移动(场上对象, 起点, 终点, 批次) | 场上地点变化；标准移动与效果移动分开，可能引发争夺／战斗 |
| `RECALL` | 召回(永久物) | 回其基地；不是回手，不算移动（456–459） |
| `DRAW` | 抽牌(玩家, 数量或指定牌) | 默认主牌堆顶到手；原文指定抽某牌时也保留抽取身份 |
| `DISCARD` | 弃置(玩家, 数量, 合法手牌集合) | 手牌直接到废牌堆，决定者与行动玩家可不同 |
| `RECYCLE` | 回收(对象集合, 所属牌堆) | 到拥有者相应牌堆底部，不是洗整个牌堆 |
| `BANISH` | 放逐(对象集合, 关联 ID) | 到放逐区，不算摧毁／弃置，保留关联 |
| `BURN` | 燃烧(玩家, 数量) | 主牌堆顶到废牌堆，保留燃烧事件 |
| `CHANNEL` | 召出符文(玩家, 数量, 入场朝向) | 顶部符文入场，默认活跃；明确休眠则休眠 |
| `ORDER` | 排序(已选牌集合, 顶／底, 顺序政策) | 玩家排序与随机次序不同，仅作用于指明集合 |
| `HIDE` | 盖放(牌, 己控战场, 权限参数) | 不算打出；费用、容量、控制条件、未来权限分别登记 |

回收多张主牌堆卡按417随机其牌底次序；多张符文回符文牌堆按拥有者选择次序。`MOVE` 不自带统一横置成本，标准移动的费用与效果移动另行处理。

规则流程 `BURN_OUT`：从主牌堆移出数量不足时，尽可能执行，回收废牌堆，选择对手得1，再继续余量（432）；连续无法恢复的情况也按该规则处理。查看、展示、洞察不足只取现有数量，不因此耗尽。不能把空牌堆简单当作抽零张。

### 5.2 打出、生成、复制和控制

| ID | 签名 | 语义边界 |
| --- | --- | --- |
| `PLAY` | 打出(牌, 行动玩家, 来源, 费用政策, 目的地, 选择) | 进入正常打出流程和链，效果授权仍保留未被覆盖的合法性要求 |
| `CREATE` | 生成(模板, 数量, 区域, 控制者, 初始状态) | 新建实例；直接生成在场上不自动算打出 |
| `COPY` | 复制(对象, 来源, 特征范围, 持续期) | 复制特征与生成复制体分开；不默认复制所有实例状态 |
| `COPY_TEXT` | 复制文本(对象, 来源, 文本范围, 持续期) | 如将宿主文字复制到装备效果区，不能复制整个实体代替 |
| `COPY_ABILITY` | 取得能力(接收者, 来源集合, 能力筛选, 持续条件) | 如黑默丁格取得友军横置能力；保留能力来源与第一人称规则，防止自引用无限展开 |
| `CONTROL` | 改变控制(对象, 新控制者, 期限／归还条件) | 不改拥有者；地点变化由另一个动作或明确规则处理 |
| `REPLACE_BATTLEFIELD` | 替换战场(原战场, 衍生物模板, 换回政策) | 按439继承状态与引用，建立原战场关联；不是普通放逐后打出 |
| `ADD_LEGEND` | 添加传奇(构筑预选引用, 期限, 移除条件) | 创建／引入传奇的具名组合，不扩大预选列表 |

`PLAY(新衍生物)` 与 `CREATE(衍生物, 场上)` 的事件不同。复制依446、479保留可复制特征，不把临时战力、伤害、增益等整份实例状态浅拷贝。

战场替换把原牌置于放逐区，但439规定它不是普通放逐动作。换回时使用关联原牌并继承当前状态。与下文替代事件的 `REPLACE` 区分。

### 5.3 状态、战力和贴附

| ID | 签名 | 语义边界 |
| --- | --- | --- |
| `EXHAUST` | 横置(对象集合, 批次) | 已横置不再次发生横置事件 |
| `READY` | 活跃(对象集合, 批次) | 已活跃不再次发生；活跃入场不是先入场再活跃 |
| `BUFF` | 增益(单位集合) | 默认每单位最多一个，每个计数物+1；已有则不再成功获得 |
| `SPEND_BUFF` | 消耗增益(己方单位引用, 数量) | 必须有可消耗计数物，不是负战力效果 |
| `STUN` | 眩晕(单位集合) | 不横置、不减战力；战斗伤害贡献受限，默认回合清理时解除 |
| `EMPOWER` | 强化(对象集合) | 默认二元状态；已有则不再次成功，明确例外可叠层 |
| `DISEMPOWER` | 解除强化(对象集合) | 多层例外每次移除一层（443） |
| `MOD_MIGHT` | 调整战力(对象集合, 加减值, 期限, 局部上下限) | 临时和持续修饰分开，不把“最低1”升级为全局规则 |
| `SET_MIGHT` | 调整至战力(对象, 目标值, 方向, 期限) | 提高至／降低至／双向调整分开，不能把提高实现为可能降低的赋值 |
| `SET_BASE_MIGHT` | 修改基础战力(对象, 值, 期限) | 不覆盖之后的增益、装备与其他修饰 |
| `SWAP_MIGHT` | 交换战力(两对象, 期限) | 434：按当时差值建立两个增减效果，不交换所有战力来源 |
| `HEAL` | 治疗(对象集合) | 清除已受伤害，伤害不是战力减值 |
| `ATTACH` | 贴附(装备, 宿主) | 关系、装备规则失活、效果文字生效、武装战力各自保留；不等于移动或活跃 |
| `DETACH` | 卸除(装备) | 恢复文本生效范围，保留地点，执行必要装备召回清理 |

增益与强化互相独立。李青、凯尔等明确例外修改各自上限，不能据此修改全库默认规则。离场和新实例产生按完整区域规则清理状态。

翻倍战力按433读取执行时战力并建立等量加值，期限内保留该加值，不是永远重新乘二。复制、特征、能力和算术效果依475–480的层次及依赖处理；不能仅按文字排列硬覆盖。

### 5.4 伤害、死亡和链

| ID | 签名 | 语义边界 |
| --- | --- | --- |
| `DAMAGE` | 造成伤害(来源, 对象／集合, 数值或分配池, 批次) | 保留责任玩家、战斗／非战斗、额外伤害、分配与重复 |
| `PREVENT_DAMAGE` | 预防伤害(对象, 来源筛选, 额度, 期限) | 延迟替代；按实际预防量消耗额度，全部预防则没有造成伤害事件 |
| `KILL` | 摧毁(永久物集合, 原因, 归属) | 场上到废牌堆，先处理替代，保留死亡与最后已知信息 |
| `COUNTER` | 无效化(链项, 离链去向修饰) | 不执行原效果，不退费用，保留离链替代 |
| `RECHOOSE` | 重做选择(链上法术, 决策玩家, 选择范围) | 可包含模式、目标和其他选择，不等于仅改一个目标，不重复已付费用 |
| `EXECUTE_TRIGGER` | 执行指定效果(来源, 触发种类, 次数) | 执行征服效果而不伪造征服、控制变化或得分事件 |

~~~text
每名敌军受到2伤害              → 一条指令，每个对象各2
在这些单位间分配5伤害          → 总伤害池5，记录分配方案
做两次：对一个单位造成3        → 两个自反待处理项，分别选择
每贴附一件武装，对一名敌军造成2 → 418.8：一次伤害，数值2×武装数
~~~

分配伤害、实际伤害、致死清理和摧毁归属不同。“分配至少5点过量伤害”不能改成实际造成至少5。指令让两个单位互相伤害时，伤害源和责任玩家仍分别来自单位及其控制者。

### 6.1 `SET_RULE` 不得是黑盒

本轮所需规则项限定如下，每条都必须携带范围、条件、期限和数值；未列明的新规则不能静默接受：

| 规则项 | 参数／作用 | 本批例子 |
| --- | --- | --- |
| 胜利门槛 | 游戏模式胜利分数的增减 | Aspirant’s Climb |
| 盖放容量 | 玩家、地点、控制条件、容量增减 | Bandle Tree、Bushwhack Trap |

## 8. 事件、状态、历史

### 8.1 事件族

| 事件族 | 必须区分的筛选 |
| --- | --- |
| 打出 | 自身／其他牌，单位／法术／装备，任一玩家／自己，第N张，来源区域 |
| 定稿 | 费用与选择完成的历史，与成功执行后的打出触发不同（420.4） |
| 入场／地点 | 打到此处、移入移出、移动起终点、进入己控战场；进入不等于进攻 |
| 战斗 | 进攻／防守、开始／结束、胜负、未受伤参战、过量伤害分配 |
| 控制／得分 | 征服、据守、Scored、增分、此前无人控制、控制变更 |
| 回合／阶段 | 指定玩家开始阶段、主阶段开始、得分前、结束阶段、未来指定阶段 |
| 死亡／离场 | 自身、其他友军、敌军、装备；死亡前增益／强化／强力；离场不都算死亡 |
| 牌堆／手牌 | 抽取、弃置、自身被弃、燃烧；查看／展示中的特殊替代 |
| 状态变化 | 增益、消耗、活跃、横置、同时横置若干、眩晕、强化／解除、变为强力 |
| 被选为目标 | 法术／能力、行动玩家、目标位置、每回合限制；不等于任何挑选 |
| 贴附 | 装配／贴附、宿主变更、卸除，与装备打出分开 |

事件族只是分类，具体能力保留精确筛选和数量。三次各横置一名单位不等于同时横置三名。

### 8.2 状态与历史

状态条件包括增益、强化、强力、在战场、进攻／防守、战场控制、活跃敌军、标签或类型存在、XP门槛等；重新计算不制造新触发。

“本回合首次”与“每回合一次可选”不同。后者按383.3可在先前事件放弃，保留以后使用。限制所属玩家、实例、回合与事件种类必须明确。

自身死亡／离场读取规定的最后已知信息；亮出读取亮出快照；其他集合统计按原文时点读取。不能统一冻结所有参数，也不能统一实时重算。

| 当我拥有增益 | 看原文区分状态条件与成功增益事件 |
| 选择标签／类型 | 选择／宣告步骤，不是触发时机 |
| 展示并打出 | 展示→选择→打出，其他放逐／回收按具体原文加入 |
| 全体伤害／分配伤害 | 同一DAMAGE，范围、池、分配、批次参数不同 |
| 从废牌／战场回手 | 普通TRANSFER；原文draw则保留DRAW |
| 回基地 | 原句move用MOVE，recall用RECALL |
| 免费／开放战场打出 | PLAY的费用政策／目的地权限，open与uncontrolled等不混用 |
| 摧毁／放逐／回收 | 分别保留动作身份，不能全用TRANSFER替代 |
| 法术技能伤害+X | MOD_DAMAGE，保留来源与受伤对象范围 |

## 11. 能暴露模型缺口的实际例子

### 11.1 Ekko, Recurrent

~~~text
事件：自身死亡（绝念）
基础费用：回收此次死亡关联的自身牌
效果：活跃己方符文
~~~

绝念不是固定组合。383.3.b规定此处开头to费用按触发能力基础费用处理，不能随意推迟到效果末尾。

### 11.2 Riven, Shattered

~~~text
自身进攻 → 选择此处一名敌军
→ DAMAGE(能力, 选定单位, 2×自身贴附武装数, 一次)
~~~

418.8规定此处乘算为一次伤害，不逐件分别造成2点。

### 11.3 Zilean, Time Mage

~~~text
每回合一次，自身在战场，自己将打出单位衍生物：
可改为打出该衍生物及一个额外复制体。
~~~

表达为事件替代＋生成复制体＋打出，不是事后触发或把总单位数直接乘二。

### 11.4 Time Warp

~~~text
结算 → 在当前回合后插入自己的一个额外回合
     → 放逐本法术
~~~

放逐不延迟到额外回合结束。仅记录回合编号变化无法表达这张牌。

### 11.5 Mystic Reversal

~~~text
选择链上法术 → 改变其控制者 → 新控制者可重做该法术的选择
~~~

控制者、模式、目标、其他选择及原费用分别保留；把它写成“区域转移”或“改一个目标”会丢失效果。

## 12. 来源缺口和覆盖限制

- Bomb缺简中来源，不生成自译当作官方文本。繁中也未覆盖全目录。
- 部分印刷缺名称、规则或装备效果区；其他牌本来就是纯属性。附录保留null，不仅凭空值判无能力。
- 同卡语言、异画、新旧印刷可能实质不一致。并列保留，人工笔记标出发现的范围、数量或时点差异；不自动翻译消除冲突。
- 勘误与原文分开。有些勘误缺URL或日期，不能把未给出的出处补成官方认证。
- 一些中文标记损坏，英文也有疑似图标问题；原始文本保留，不能自动“纠正”。
- 如Smolder, Fired Up基础战力缺失，生成模板中的数值不直接写回基础字段。

这些是资料问题，不是增加一个万能算子能解决的问题。未来精确转换遇到冲突必须显式待核，不能输出猜测结果。附录算子词汇是人工阅读索引，不是每个句段已经完成可执行映射的证明。

## 13. 扩展规则和完成标准

每张新增牌依次读取属性、所有玩法文本区、所有可用中英文变体、背面及勘误。先匹配既有动作；对象、数量、区域、费用政策、持续期不同优先扩展参数。独立规则动作、事件身份或组合结构确有差异，才新增词汇。

| 本轮批次 | 促成的主要扩展 |
| --- | --- |
| 0001–0300 | 召回、动作身份、装备双文本、受限资源、死亡替代、控制、战场替换 |
| 0301–0600 | 复制、伤害预防、费用时点、选择归属、基础战力、额外触发、强化XP |
| 0601–0800 | 延迟／自反链项、放逐关联、重做选择、执行征服效果、额外传奇、状态上限 |
| 0801–1000 | 批量横置、盖放信息权限、武装复制、增分限制、效果区缺文、额外回合 |
| 1001–1106 | 过量伤害分配、延迟死亡替代、受伤来源过滤、衍生物复制打出 |

固定快照中1,106个编号均有记录，34个目录键均有说明，附录使用的76个ID全部在本文登记。**76是跨层次词汇数，不是76个同层级基本算子。**

精确转换的100%验收还必须检查：每个玩法句段都有节点；数值、主体、目标、费用和时点均保留；每个关键词有明确展开；每个引用可追溯；无未映射语句；无未解决来源冲突。仅卡牌条数相等或每张有一个标签不能算通过。未知语句必须显式失败，不得塞进SET_RULE或NONE。

## 14. 当前项目边界
