# 第三轮全库阅读与文档校核结果

日期：2026-10-28。[覆盖报告](../card-api-coverage.md) · [逐卡阅读索引](../card-operator-reading.md) · [冻结的V3 API](../basic-operators-api-v3.md) · [冗余审查](round-3-redundancy.md)

## 结论与统计口径

本轮完整阅读1106个卡牌本体，并逐卡记录API分解、条件、参数和问题。确认覆盖1059张，待核验7张，未完整覆盖40张，**确认覆盖率为95.75%**。V3尚未达到全库100%覆盖。

| 指标 | 结果 | 说明 |
| --- | ---: | --- |
| 本体完整阅读 | 1106/1106，100.00% | 编号连续且本体不重复；每张有本轮独立阅读结论 |
| 确认覆盖 | 1059/1106，95.75% | 排除待核验、API缺口及已知语义错误 |
| 候选结构表达 | 1066/1106，96.38% | 包含7张待核草稿，不能视为确认覆盖 |
| API调用签名符合 | 2335/2335，100.00% | 调用名、必需参数、未知参数、重复参数及位置参数数量符合文档 |
| 独立语义正确率 | 未测得 | 没有独立裁判真值集及执行引擎，不能据签名符合率宣称语义100%正确 |

确认覆盖是本轮人工审阅结论，不是实战正确概率或完整规则认证。未覆盖卡也保留能表达的能力片段及候选调用；仅有动作体可表达，不能抵消触发入口、费用政策或规则范围尚未表达的问题。

## 阅读来源与原文留存

本轮读取本地目录9039条印刷所对应的2771组不同EN／SC／TC规则及装备效果文本、基础属性、背面信息和73条目录勘误。没有逐图检查9039张印刷图片，不能将文本全读等同于全库视觉核验。

| 项目 | 校核结果 |
| --- | --- |
| 原始规则／装备效果字段 | 5542个，均与目录一致 |
| 文本组来源指纹 | 1106张均与目录提取结果一致 |
| 逐卡本轮阅读结论 | 1106条，内容各自独立 |
| 逐卡R3记录区块 | 每张恰好一个，旧轮次保留为历史 |
| DATA来源问题 | 49张另有记录，不擅自补值 |
| LANG语言／版本差异 | 51张另有记录，不擅自统一原文 |

DATA与LANG集合可能重叠，也不直接等于未覆盖集合。确认覆盖针对本轮采用的可核对规则语义，不意味着每一语言、每一印刷都不存在缺文或版本差异。各卡采用的解释及保留问题见逐卡记录；Bomb缺少SC卡面，TC仅覆盖321个本体，不能声称中英文及繁中资料均已齐全。

## 调用与引用校核

- API包含71个正式函数，当前分解显式使用70个；`reorder`未独立出现，分析见冗余审查。
- 2335次`ops`调用没有未知函数、签名错误或旧版`ready`、`exhaust`、`empower`、`disempower`调用。
- 参数绑定检查未发现未声明的普通变量；费用选择参数没有发现与`CostSelection`约定不符的绑定。该检查只检验声明一致性，不证明参数在真实局面下必然存在。
- 原文字段比较没有差异；本轮文档初次校核的7898处本地链接没有断链。此数值是当时文档快照的链接数，不是卡牌或能力数。
- 没有运行项目测试套件，没有执行游戏效果、矩阵转换或模拟。

机器可读校核记录保存在[本轮校核记录](../../tmp/card-api-v3-final-validation.json)，逐卡审阅账本保存在[本轮阅读账本](../../tmp/card-api-review-v3.jsonl)。这些记录支撑文档一致性，不能替代规则语义裁定。

## 影响覆盖结论的主要规则边界

24张未覆盖卡涉及“打出”触发的成功结算时点。核心规则420.4.a与420.4.b区分成功结算后的打出触发和按定稿统计的历史；V3的`PLAY.finalized`不能代替前者，`entered`也不足以覆盖法术。其余缺口涉及战斗结束、盖放、主动能力使用、弃置／放逐事件、消耗增益、状态跨阈值，以及强制打出目的地的冲突仲裁。全部卡名和逐卡原因见覆盖报告。[核心规则PDF](https://cmsassets.rgpub.io/sanity/files/dsfx7636/news_live/5c7946f7c3b8c6e0faff85ab6dadc6d2e721ea94.pdf)

本轮还据官方资料校正了费用结算顺序、原始召唤符文数量、期限终点，以及The Exile的位置判定等分解；这些校正已写入对应卡的R3记录。[Radiance规则FAQ](https://playriftbound.com/en-us/news/organizedplay/radiance-rules-faq-and-clarifications/)
