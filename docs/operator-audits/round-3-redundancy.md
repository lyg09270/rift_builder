# 第三轮基本算子简化与冗余审查

日期：2026-10-28。[本轮V3 API](../basic-operators-api-v3.md) · [修订依据](../card-api-changes-v3.md) · [覆盖报告](../card-api-coverage.md)

## 已完成的合并

| 原V2.1函数 | V3函数 | 合并条件 |
| --- | --- | --- |
| `ready`、`exhaust` | `orient(objects, state, ...)` | 朝向使用闭集参数；两种游戏动作的事件身份、费用要求和实际变化结果仍分别保留 |
| `empower`、`disempower` | `change_empowerment(objects, mode, ...)` | 模式使用闭集参数；获得／移除的事件身份、叠层例外、移除数量仍分别保留 |

四个入口合为两个，**正式函数由73个简化为71个**。四个旧名不再是合法调用别名。本轮1106张卡的分解均采用V3入口，没有残留旧函数调用。

## 未使用函数与后续简化空间

2335次显式调用涉及71个函数中的70个；`reorder`没有独立调用。与排序有关的已读卡牌通常由`predict`等已定义规则宏封装。

这说明`reorder`存在入口精简的审查空间，但不能据此认定它与`predict`重复：前者处理指定集合的顺序及位置，后者具有查看、可选回收等额外语义，两者不能直接互换。若以后将API严格限定为当前卡库的显式最小集合，可以考虑移除这一独立入口，同时检查宏内部是否仍引用它；本轮保留冻结的71函数版本，未在阅读后改变统计口径。

## 功能相近但不能直接合并的函数

| 函数组 | 保留原因 |
| --- | --- |
| `draw`／`transfer` | 抽牌具有专门规则与事件；普通区域转移不能抹去动作身份 |
| `kill`／`banish`／`recycle`／`discard`／`burn` | 来源约束、替代效果、费用用途、事件身份不同 |
| `move`／`recall` | 移动权限、位置限制与触发不同 |
| `buff`／`spend_buff` | 获得上限、消耗权限、实际消耗回执不同 |
| `attach`／`detach` | 宿主关系、目标与返回结果不同 |
| `modify_might`／`set_base_might`／`modify_equipment_bonus` | 操作的规则层不同，持续修饰下不能按最终数值相同合并 |
| `copy`／`copy_text`／`copy_abilities` | 复制对象与字段、动态能力集合及递归约束不同 |
| `grant_ability`／`grant_keyword`／`modify_keyword` | 新能力、关键词身份及修改既有参数不同 |
| `on_event`／`replace_event`／`queue_effect` | 触发、替代与生成后续处理项的时点不同 |
| `change_control`／`end_modifier` | 建立控制修饰与结束指定修饰不同 |

本轮没有再确认可无损删除的等价函数对。当前40张未覆盖卡的主要问题是事件与规则契约缺口，并非通过继续合并动作函数即可解决。新增事件种类、阶段或字段不必增加函数数量；若修订这些契约，应形成新版本并重新评估受影响分解。
