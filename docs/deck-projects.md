# Deck project management

Use `scripts/deck_projects.py` for project operations. Card validation and RiftAtlas export are internal dependencies in `scripts/deck_support.py`, using the unchanged bundled data in `data/`. The former retrieval and recommendation skill has been removed.

## Storage layout

```text
decks/
├── active/<project-id>/
│   ├── project.json
│   ├── build-session.json
│   ├── build-history/
│   ├── deck.json
│   ├── validation.json
│   ├── riftatlas.txt
│   └── revisions/0001/...
├── archive/<project-id>/...
└── .data_versions/<version-id>/
    ├── cards.sqlite
    ├── rules.json
    └── version.json
```

- `deck.json` is the validated current source; edit a separate candidate JSON and save it through the CLI.
- `build-session.json` records the current guided-pipeline stage and accumulated construction decisions.
- `build-history/` contains recoverable snapshots created before session updates.
- `validation.json` is the current legality evidence.
- `riftatlas.txt` is the current final RiftAtlas import file.
- `revisions/` contains immutable snapshots, reasons, metadata, and card/strategy diffs.
- `.data_versions/` deduplicates exact card database and rules snapshots so an old revision can be reproduced later.

Managed files are generated by the CLI; `riftatlas.txt` is derived only after successful validation. An unfinished build has no validated deck/export; its draft lives in the session state.

## Commands

Deck input follows [the canonical schema](deck-schema.md). Bundled data provenance is recorded in [data/README.md](../data/README.md).

All commands print JSON and return `0` on success or `2` on failure. Commands below run from the workspace root.

Create a project from a validated canonical deck:

```text
py -3 scripts/deck_projects.py create --name "Rengar Radiance" --project-id rengar-radiance --deck path/to/deck.json
```

Start and resume an unfinished guided build:

```text
py -3 scripts/deck_projects.py start-build --name "Rengar Guided" --project-id rengar-guided --entry-mode hero_first
py -3 scripts/deck_projects.py build-status rengar-guided
py -3 scripts/deck_projects.py build-update rengar-guided --stage requirements --state path/to/state-update.json --note "Confirmed hero-first entry"
py -3 scripts/deck_projects.py build-update rengar-guided --state path/to/current-state.json --note "Saved player decision"
```

Advance through the pipeline stages in order. From `review`, after the review is complete, enter `final_confirmation`. After the player approves the exact complete draft, persist that confirmation and finalize it:

```text
py -3 scripts/deck_projects.py build-update rengar-guided --stage final_confirmation --state path/to/final-state.json --note "Review complete; awaiting player approval"
py -3 scripts/deck_projects.py build-update rengar-guided --state path/to/approved-state.json --note "Player approved exact final draft"
py -3 scripts/deck_projects.py finalize-build rengar-guided --deck path/to/final-deck.json
```

Save a new revision:

```text
py -3 scripts/deck_projects.py save rengar-radiance --deck path/to/revised-deck.json --reason "Improve early battlefield pressure"
```

Optional `--metadata path/to/object.json` on `create` or `save` records structured information without changing the deck schema.

Inspect projects:

```text
py -3 scripts/deck_projects.py list --include-archived
py -3 scripts/deck_projects.py show rengar-radiance
py -3 scripts/deck_projects.py history rengar-radiance
```

Restore revision 1 as a new revision, preserving all history:

```text
py -3 scripts/deck_projects.py restore rengar-radiance 1 --reason "Return to the original build"
```

Copy or archive projects:

```text
py -3 scripts/deck_projects.py copy rengar-radiance --name "Rengar Experiment" --project-id rengar-experiment
py -3 scripts/deck_projects.py archive rengar-experiment
py -3 scripts/deck_projects.py unarchive rengar-experiment
```

Reproduce a revision against its exact stored database and rules snapshot:

```text
py -3 scripts/deck_projects.py verify rengar-radiance
py -3 scripts/deck_projects.py verify rengar-radiance --revision 1
```

Use global `--projects-root`, `--db`, or `--rules` options before the subcommand when a non-default location is required.


## Session stage persistence

Stage IDs remain available for reading and resuming existing projects: `entry`, `requirements`, `identity`, `brief_confirmation`, `core_plan`, `deck_skeleton`, `card_selection`, `resources`, `review`, `final_confirmation`, `completed`. They record project progress; no automatic recommendation or card-selection workflow is attached.

Existing project files, revision snapshots and source data versions are preserved. Their historical metadata is not rewritten during the source-code cleanup.
