# NumPy 局面优势向量

实现：[scripts/game_state.py](../scripts/game_state.py)。依赖：`python -m pip install -r requirements.txt`。

`game_state` 用于表示当前局面中双方的资产、资源、行动余地和计分位置，不是完整规则执行器。它只保存一个形状为 `(93,)` 的 `float64` NumPy 向量；`StateEnum` 只定义维度索引，每项均写明整数编号，不使用 `auto()`。当前没有评分权重或胜率输出。

## 规则依据与采样范围

依据项目内的 [2026-10-09 官方核心规则](references/riftbound/riftbound-core-rules-2026-10-09-en.pdf)，限定标准双人、两个战场、目标 8 分。`VICTORY_SCORE=8` 是规则配置常量，不占动态维度；不支持修改胜利阈值的模式或效果。

比较时在 Chain 及相关触发结算、清理完成后的 Open 时点采样，可以是 Neutral Open 或 Showdown Open。不对尚在 Chain 上的效果估值，不推断 Priority、Focus 或行动合法性。`TURN_PLAYER`、`PHASE`、`WINDOW` 是解释行动与资源时效的条件，不是“越大越好”的优势分。

P0 固定表示己方，P1 表示对手；未知信息不能用零填充。未来外层上下文负责由实际卡牌明细生成这些汇总量，本轮不实现外层类。

## 向量布局

| 下标 | 内容 | 维数 |
| --- | --- | --- |
| 0–2 | 回合玩家、阶段、Open 窗口类别 | 3 |
| 3–4 | 双方得分 | 2 |
| 5–14 | 双方主牌库、符文牌库、手牌、墓地、英雄区数量 | 10 |
| 15–30 | 双方当前浮动 Energy 与六领域及 Universal Power | 16 |
| 31–44 | 双方六领域场上符文数量、就绪符文总数 | 14 |
| 45–46 | 双方 XP | 2 |
| 47–48 | 双方场上非单位装备总数，包括附着和具有 Deploy 的装备 | 2 |
| 49–58 | 双方基地单位数、总战力、就绪单位数、就绪战力、标记伤害总数 | 10 |
| 59–75 | 战场 0 控制者、双方单位数／总战力／就绪数／就绪战力／非晕眩战力／标记伤害／盖放数／Scored 标志 | 17 |
| 76–92 | 战场 1，同上 | 17 |

维度索引占用 0–92，代码明确声明 `STATE_SIZE = 93`。`StateEnum` 中每个成员都对应一维，`len(StateEnum)` 同样为 93；玩家编号、阶段取值等不混入维度枚举。

字段取值在校验中限定：`TURN_PLAYER` 为 0（己方）或 1（对手）；战场控制者还可取 -1（无人控制）；`WINDOW` 为 0（Neutral Open）或 1（Showdown Open）。`PHASE` 的 0–8 依次表示准备、唤醒、开始、计分、引导符文、抽牌、主要、结束、到期。Scored 标志取 0 或 1。这些数是维度里的值，不是新增维度。

## 这轮调整的判断

### 保留：资产、可用资源、位置和通用计分历史

- 得分、手牌与英雄区数量表示胜利进度和可打出卡牌的储备。英雄区的牌可以从该区域打出，不能直接计入手牌（108.3）。
- 主牌库与墓地数量保留：Burn Out 会回收墓地、给对手 1 分，再继续原操作，牌库空并不直接等于输掉游戏（432）。这些数量不是单调的优势。
- 保留符文牌库数量，描述后续 Channel 的储备；保留分色浮动 Power，不能把全部颜色资源合并成一个数（163、431）。
- 战场控制者、盖放卡数量、双方每战场 Scored 标志保留。控制关系决定 Hold、盖放与收益；Scored 和实际增加分数不是同一件事，最后一分的征服还读取“本回合是否已 Scored 每个战场”（107.3、469–473）。
- 基地与战场分别记录单位：标准移动的目的地有区别，普通单位不能直接从一个战场移向另一个战场，Ganking 才改变该限制（144）。

### 增加：把行动、战斗、存活压力分开

| 字段 | 明确定义 | 依据与作用 |
| --- | --- | --- |
| `*_READY_UNITS` | 未横置单位数量；原有字段保留 | 标准移动需要支付横置费用；表示行动余地，不表示无条件可以行动（144） |
| `*_READY_MIGHT` | 未横置单位的当前有效战力之和 | 增加 6 维；区分“就绪的是大单位还是小单位” |
| `BF*_P*_COMBAT_MIGHT` | 战场上非晕眩单位的当前有效战力之和，不排除横置单位 | 增加 4 维；晕眩不贡献战斗伤害，横置本身不取消战斗贡献（424、467） |
| `*_DAMAGE` | 该位置己方仍在场单位的标记伤害总和 | 增加 6 维；伤害不降低 Might，但会降低后续致死伤害所需数量；战斗清理和回合结束会治疗（142、143.3、467–468） |
| `P*_RUNES_<DOMAIN>` | 按六个领域分别统计场上符文，含就绪与横置 | 增加 12 维；基础符文可回收产生对应颜色 Power，回收本身不要求就绪（164.2） |
| `P*_XP` | 玩家持有的 XP | 增加 2 维；XP 是规则中的玩家资源，能支付并满足 Level 条件，不是推测的未来机制（727–730） |
| `P*_GEAR_COUNT` | 全场非单位装备数量，按当前控制者统计 | 新增 2 维替代原有 2 维基地装备数；规则支持附着装备，不能只观察基地（147–150、718–719） |

`MIGHT` 始终对各单位取规则引用值 `max(0, effective_might)` 再求和，不减去伤害。`READY_MIGHT` 同样只对未横置子集求和。`COMBAT_MIGHT` 只排除晕眩，不是包含 Bonus Damage、伤害替代或预防后的伤害预测。就绪与晕眩是不同属性，不能把晕眩等同于横置。

就绪符文总数已经单独保存；横置符文总数可由六色符文总和减去就绪数推导，因此删除其 2 个独立维度。基础符文可以先横置产 Energy，再回收产 Power；这些是可选择的操作，不会自动加进浮动资源池。特殊符文能力仍需卡牌明细。

### 删除或移出：不是通用优势量的内容

- 删除 12 个本回合打出／抽牌／弃牌／死亡计数。它们可能决定具体卡牌，但不是通用优势分；数量也无法表达“非衍生装备打到某战场”等精确条件。未来由外层历史与能力实例负责。
- 删除全局回合号、Priority、Focus、状态、胜者和目标分数共 6 维。回合号及行动权属于流程／卡牌条件，结果属于外层生命周期；目标分数在当前规则配置中固定。保留回合玩家与阶段用于比较资源刷新前后的局面。
- 删除战斗位置、攻守双方、战斗阶段、Chain 长度、待处理触发／任务数、待选择玩家、连续让过、待清理共 10 维；删除两个战场的发起争夺者共 2 维。这些需要完整执行上下文，不能通过几个数量重建，将它们放进优势向量也不会使向量具备结算能力。
- 删除放逐数量 2 维。放逐区内容可能有回收／联动价值，但单纯数量没有统一的资产解释，未来按具体卡牌查询。
- 删除原有横置符文数 2 维、基地装备数 2 维，分别由可推导量与全场装备计数替代。

总计删除旧字段 36 个、加入有明确定义的新字段 32 个，97 维调整为 93 维。目标不是单纯缩短向量，而是让每一组保留的观测都有规则和局面判断上的含义。

## 使用

将工程 `scripts/` 加入导入路径后：

~~~python
import numpy as np
from game_state import StateEnum as S, game_state

state = game_state()
state.update({
    S.TURN_PLAYER: 0,  # 己方回合
    S.PHASE: 6,       # 主要阶段
    S.P0_SCORE: 2,
    S.P0_HAND_COUNT: 4,
    S.P0_ENERGY: 3,
    S.P0_RUNES_BODY: 2,
    S.P0_RUNES_FURY: 1,
    S.P0_READY_RUNES: 2,
    S.P0_BASE_UNITS: 2,
    S.P0_BASE_MIGHT: 6,
    S.P0_BASE_READY_UNITS: 1,
    S.P0_BASE_READY_MIGHT: 4,
})
next_state = state.copy()
next_state[S.P0_ENERGY] = 1
matrix = np.stack([state.to_vector(), next_state.to_vector()])
~~~

`state.vector` 是唯一存储；构造、`copy()`、`to_vector()` 都复制数据，避免分支共享。`update()` 整体校验后提交；直接写向量后调用 `validate()`。校验包含类型、形状、数值域、就绪数与总数关系、战力子集关系等，不负责自动推导或执行规则。

新卡牌模型的 `Card.cost()` 不读取被删除的出牌历史。涉及 Legion 时，调用者必须在 `CardContext` 中显式提供 `played_other_card=True/False`；不提供会报错，不默认其未触发。该参数是历史事实，不是概率。墓地降费继续读取向量中的墓地数量。事件接口和使用方式见 [卡牌转换文档](card-transitions.md)。

## 尚不能表达的局面差异

相同总战力和总伤害可能对应不同的单位分布，伤害分配、Tank、Backline、临时增益到期、目标抗性、装备效果、卡牌质量和连携价值都需要未来的逐卡上下文。隐藏牌的身份也不包含在公开数量中。当前向量不能精确判断战斗结果，不能单独判断谁必胜。

分类编码不具备数值大小上的优势含义；不同维度也不能未经权重校准直接求和。观测的概率期望不一定是合法实体局面，分类分支应分别保存。

默认值是空的准备阶段快照，不是官方开局或缺失数据。旧 97 维向量不兼容新布局，没有保留兼容层。后续卡牌转换任务中，用户明确要求新增并运行语义测试与全牌库验收；这不改变默认未经要求不添加测试的约定。
