# 基本算子 API：第二轮修订依据

[V2 API](basic-operators-api-v2.md) · [第二轮逐卡报告](card-api-coverage.md) · [冗余核查](card-api-overlap.md) · [第一轮存档](card-api-coverage-v1.md)

第一轮全量阅读结束后，以其未覆盖项与接口重叠为依据修订。V1的69个函数归并减少5个入口，再增加8个缺失机制，V2共72个正式函数。旧名不作为别名保留。

| 第一轮问题 | V2修订 |
| --- | --- |
| 获得／消耗经验分成两个入口 | `change_xp(mode="gain"/"spend")`；保留动作身份、余额检查和费用角色 |
| 战力增加、设至、交换分散 | `modify_might`使用互斥add/set/swap，交换使用共同快照；基础战力仍独立 |
| 额外传奇生成单独入口 | `create(SetupChoiceRef,...)`及带类型的创建回执，预选不能凭空捏造 |
| 战场替换与还原重复入口 | `replace_battlefield(mode="replace"/"restore")`，保留原战场关联 |
| 双方互殴、跨玩家指令或同时交换缺批次 | 新增`batch`，明确共同快照与多玩家程序顺序；移动支持LocationMap |
| 延迟触发、下一张牌关联、过程内步骤不能表达 | 新增`on_event`，区分triggered与inline，保留真实事件、来源、控制者和消费点 |
| 死亡前替代、流转离链、展示前查看缺接口 | 新增`replace_event`，替代程序与付款门槛显式定义，事件及patch均封闭登记 |
| then do this被误作立即执行 | 新增`queue_effect`，建立新的待处理项，普通then仍在原项内执行 |
| 活跃／休眠入场被写成状态改变 | 新增`modify_entry`；ready/exhaust扩展至Orientable，含符文和传奇 |
| 装备贡献层被普通战力增益替代 | 新增`modify_equipment_bonus`，逐装备保留贡献归属 |
| 据守与征服触发互增无法表达 | 新增`modify_trigger_events`，只开放明确两类互增 |
| 宣告值与构筑选择缺持久关联 | 新增`remember`，字段须声明类型及作用域 |
| 行动玩家被对象拥有者混淆 | 为展示、转移、移动、召回、回收、放逐、伤害、摧毁增加actor契约 |
| play仅返回链项导致把链项当Unit | PlayReceipt区分item/card、付款、选择和实际入场对象；类型转换亦提供单位视图 |
| 分次展示预先偷看未知牌 | reveal支持授权来源逐张展开及停止条件，返回实际展示集合 |
| 可选优惠被强制消耗、重复费用或免费打出 | UsageLimit、CostBinding、付款回执、权限与目的地关联分别规定 |

第二轮仍完整重读全部卡牌，而非只检查第一轮失败卡。每张保留本轮阅读判定、参数绑定、调用及未决项；所有原始文字留存。第二轮出现的新缺口在报告中列出，不通过临时创造事件名或未登记参数强行计为覆盖。

复核期间对付款门槛及清理时机作过契约澄清：链项结算中不得Cleanup，伤害后实际死亡不能预判。各逐卡记录保留当时API指纹，最终结构核查对照当前文件；这不是各次记录都来自同一未变化文件的声明。

覆盖率与文档正确率采用1106个本体为固定分母，待核规则和未完整覆盖均不能计为正确。最终数值及阅读是否完成以[当前报告](card-api-coverage.md)为准。未逐图核验所有卡图，也没有执行引擎、对局测试或独立裁判真值认证。
