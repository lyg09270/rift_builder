# 卡牌基本模型 V1

```text
卡牌 = 基础属性 + 能力列表
能力 = 入口集合 + 效果程序 + 可选约束
```

## 1. 卡牌

基础属性保存编号、名称、类型、领域、费用、战力和标签等卡面信息。未知值保留未知，不当作零。

一张卡可以有多个能力。关键词按其定义展开为能力或规则修饰，避免重复执行。

## 2. 能力

| 部分 | 内容 |
| --- | --- |
| 入口集合 | 何时生效：入口类型、有效区域、匹配条件；事件入口还要指定事件种类、阶段和匹配粒度 |
| 效果程序 | 做什么：算子调用，以及顺序、分支、选择、重复和同时批次 |
| 可选约束 | 特殊费用、目标／模式规则、次数限制、持续期限及取值时点；只省略已有明确默认规则的项 |

入口类型分为：

- **直接结算**：法术等在轮到自身结算时执行程序。
- **主动**：玩家申请使用，经权限、选择和费用流程处理。
- **事件触发**：匹配指定事件后创建待处理能力项。
- **持续**：登记修饰，依赖变化时重新计算。
- **替代**：登记规则，在匹配动作发生前改写或替换该动作。

不同能力分别保存。同一能力可以有多个入口，共用效果程序；各入口可以有独立条件。同一实际事件通过多个事件视图命中同一触发条件时去重，不同真实事件分别处理。

## 3. 效果程序与约束

算子负责游戏动作，例如抽牌、移动、伤害、摧毁和放逐。选择、付款、批次和调度由统一流程处理，程序在指定位置引用这些流程。

需要明确以下区别：

| 规则 | 记录位置与含义 |
| --- | --- |
| 生效条件 | 入口条件在入口时检查；指令条件在执行到该处时检查；持续条件随依赖变化检查 |
| 对象与选择 | 指定决策者、候选范围、是否目标、信息权限和选择时点；已定稿目标不随意重选 |
| 费用 | 区分定稿费用与指令内付款；在各自时点处理，不全部提前支付 |
| 次数 | 分开记录事件匹配粒度、历史序号、使用额度和程序重复次数；额度还需明确共享范围、重置及消耗时点 |
| 期限与取值 | 期限附在对应修饰或登记项上；每个引用明确实时读取还是使用此前快照 |
| 结果关联 | “该牌”“如果这样做”等引用具体对象和实际动作回执，不只记录一个成功布尔值 |

## 4. 统一处理流程

普通结算路径：

```text
识别入口并检查条件、次数
→ 建立待处理实例
→ 按规定时点选择、计算费用、付款并校验合法性
→ 按链与优先权规则调度，保留立即结算分支
→ 执行效果程序
→ 保存实际结果，发布事件，登记后续项和清理任务
```

持续与替代入口分别进入修饰重算、动作前替代路径。每个动作提交前应用相应限制、修饰和替代；执行后记录实际完成部分。新的触发和清理交给规则调度器，不任意打断当前结算。

每次发动生成独立的**结算实例**，保存来源实例、相关玩家、选择、必要快照、局部变量和结果。拥有者、控制者、行动者与决策者分别绑定；事件历史和执行上下文独立保存，不混入卡牌静态属性或数值观察向量。

## 5. 多入口示例

[Scrapheap](card-operator-reading/0801-0900.md#card-0812)的同一能力：

```text
入口：被打出 OR 被弃置 OR 被摧毁
阶段：分别匹配成功结算、实际弃置完成、实际死亡事件
程序：抽一张牌
```

三个入口共用能力体，player绑定该次能力的控制者：

```python
ops.draw(player, 1)
```

具体动作签名见[V4基本算子参考](basic-operators-api.md)，节点与调度见[V4程序与流程契约](card-resolution-v4.md)，旧接口去向见[V4迁移表](card-api-changes-v4.md)。
